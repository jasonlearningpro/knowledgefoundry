Change how an item looks (states)

A state is another way an item can look. A button can look different when the pointer is over it, once it has been chosen, or when it is locked. A state changes the look only: color, outline, see-through level or which picture shows. It never changes the words or moves anything.

  1. Select an item, then find States at the bottom of Properties.
  2. Add a state: Hover, Selected, Visited, Disabled, or Your own.
  3. Change what you want to look different, such as the fill or the text color. Anything you leave alone stays as it is in Normal.
  4. Use Show on stage to see the item in that state while you work. It is only a view; nothing is saved by looking.

What each one does:

  • Hover shows while the pointer is over the item, and also while the item has keyboard focus, so people using the keyboard get the same feedback.
  • Visited shows after the learner has chosen the item once on this visit to the screen.
  • Selected, Disabled and your own states show when a trigger asks for them. In Triggers, add the action Put an item in a state. For example: when the learner selects Option A, put Option A in the Selected state. Choose Normal to put an item back.
  • Disabled also stops the item being chosen. It stays on the screen and a screen reader says it is unavailable. Use it to lock a button until something else has happened.

Make a change people can see without color. Some people cannot tell colors apart, so when it matters also change the outline or the words. The checks before publishing look at the colors of every state, and warn when text is hard to read. A disabled item is not checked, because it is not meant to be read as a control. Selected buttons are also announced to screen readers as pressed.

Good to know. A state you add but no trigger ever uses (other than Hover, Visited and Disabled) is flagged, because learners would never see it. Removing a state removes the trigger actions that used it. Hover is not used on a touch screen, because there is no pointer.
