Make a screen respond (triggers)

Use a trigger when something should happen on a screen without sending the learner to another screen: a hint that opens, a note that appears, a counter that goes up. Wires on the Flow Canvas still decide where the course goes next.

  1. Select the screen on the Flow Canvas, then open Build → Triggers.
  2. Select + Trigger. A trigger reads like a sentence at the top: When the learner selects Show a hint: show Hint note.
  3. Choose When: the learner selects an item, the screen starts, or a variable changes (to anything, or to one value). Plugins can add their own choices at the end of the list, with their own settings.
  4. Optional Only if: a test that must be true, such as clicks >= 3.
  5. Under Then, add actions: show, hide or show/hide an item; change a variable; or continue along an exit. Plugins can add their own actions at the end of the list. They run in order. Use the arrows to reorder.
  6. If a trigger uses a plugin that is not installed, it is kept as it is and does nothing until the plugin is back. The check before you publish warns you about it.

Hide something until it is needed. Select the item on the stage and choose Hidden at start in the floating palette. A trigger can show it later. A hidden item is not in the tab order and a screen reader does not read it until it is shown.

Send the course on from a trigger. Add the action Continue along an exit and name it, for example next. The screen's card on the Flow Canvas gets an Exit: next socket. Connect it to the next screen as you would a button. This is how "open all three tips, then Continue" moves on.

Items that only a trigger uses do not need a wire. The Not connected warning is not shown for them.

The checks tell you when a trigger uses an item that is gone, when it waits for something that does not act as a button, and when an item is hidden but nothing shows it. The live preview and the exported course both run triggers.
